# 交接块

**跨上下文边界的载体，不是需求摘要。**

## 什么时候写

- 要跨 session 继续
- 上下文将满
- **同一次会话接着做 L2 → 不写**，把"承重事实"一节贴到 frame 末尾即可

触发条件是**边界**，不是阶段完成。

## 模板

```markdown
# <项目> · 交接块

**目标**（一句）：…

**承重事实**（改了就会毁掉设计的东西，每条带锚点）
- 输入通道可能没有 ADB，探针必须先于架构 · §4 D4
- 微信模板消息放不下正文，长文需外链 · §4 D1
- 风控不可被策略绕过，策略不得直接下单 · §4 D6

**分诊**
| 类别 | 内容 | 锚点 |
|---|---|---|
| 已冻结 | … | §4 D2·D5 |
| 必须回答 | … | §3 #13 |
| 留给你 | … | §3 #5 |
| 明确不做 | … | §2 |

**未决**
- …（没有就写"无"）
- 我按推荐取了默认：…（可推翻）

**引用**：`docs/frame/<slug>.md`，先读 §4 与 §6
```

## 三条纪律

1. **不复述需求。** 范围、验收、三轴都在 frame 里；搬过来就是第二份，两份会漂移。
2. **承重事实必须是推论，不是决策本身。** "通道 = 微信"是决策；"模板消息装不下正文，必须外链"才是承重事实——后者用户没拍板过，下游却会被它打死。
3. **每条带锚点。** 没有锚点说明你在凭印象写，下游也无法核实你依据的是哪一版。

## 不合格的样子

| 症状 | 为什么不合格 |
|---|---|
| 出现"做什么 / 不做什么"的完整清单 | 那是 frame 的 §1–§2，等于第二份文档 |
| 承重事实写成"注意性能""要考虑扩展" | 不是约束，是口号 |
| 条目没有锚点 | 无法核实，也无法追溯 |
| 超过 20 行 | 你在写第二份 frame |

## 谁读它

跨 session 的下一次开工。读完应当知道三件事：**哪些不能动、哪些必须自己答、去哪看细节**——但不指望它替代 frame。
