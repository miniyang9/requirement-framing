# 交接块

L1 的唯一出口。签完字才写，写完才交棒。

## 模板

```markdown
# <项目名> · 交接块

- **范围**：做什么 / 不做什么（不做的写理由）
- **验收**：3–5 条可执行判据（能跑、能复现）
- **三轴**：体量档 T_ ｜ 范围方案 _ ｜ 执行档 _
- **已冻结**：技术栈、平台、合规、预算、时区…（下游不得改）
- **必须回答的设计问题**：3–5 条（从失败预演与"待定"项里抽）
- **留给下游决定的**：这些不审
- **引用**：`docs/frame/<slug>.md`（细节在那里，不必重读全文）
```

## 三条纪律

1. **只写已确认的。** 没确认的进"必须回答的设计问题"，不要写成结论。
2. **不超过 15 行。** 超了说明还有东西没定完，回第 2 步。
3. **不写实现方案。** 交接块回答"要做什么、约束是什么、还缺什么"，不回答"怎么建"。

## 不合格的交接块长什么样

| 症状 | 为什么不合格 | 改法 |
|---|---|---|
| 范围里全是"做什么"，没有"不做什么" | 没有边界的范围等于没范围 | 补"不做"，并写理由 |
| 验收写成"功能正常""体验良好" | 不可执行，下游无法判定完成 | 换成可运行、可复现的判据 |
| "必须回答的设计问题"是空的 | 说明你没想，或者你已经替他决定了 | 从失败预演里抽，至少 3 条 |
| 超过 20 行 | 里面混进了背景、历史、方案讨论 | 删到 15 行以内；细节留在 frame |
| 出现"建议用 X 框架" | 那是设计，不是交接 | 移到"留给下游决定的" |

## 谁来读它

下游（`solution-design` 或执行流）**只读这一个文件**就能开工。如果它读完之后还要回头翻 frame 全文才能动手，说明交接块没写完。
