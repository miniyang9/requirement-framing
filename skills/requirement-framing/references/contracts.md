# 契约、骨架与任务卡（L3–L7）

## 一、什么该是契约

判据只有一条：

> **会被两个以上并行单元同时读写的东西，必须是契约；其余不该是。**

契约太少 → 必然阻塞，得串行去补信息。
契约太多 → 前期成本高，而且过早锁定了一个可能错的东西。

n 个并行单元若靠两两协商，成本是 **n(n−1)/2**；收敛到 k 个共享契约，成本是 **O(n)**，且新单元加入时不用重谈。**找"最小充分共享集"是这一级的全部工作。**

## 二、常见系统的六个契约（示例，不是教条）

| 契约 | 定义者 | 消费者 | 关键内容 |
|---|---|---|---|
| 世界/领域快照 | 架构 | 所有读状态的模块 | 状态 ID、关键量、可用动作、置信度 |
| 状态/术语词表 | 架构 | 识别层、控制层 | **封闭集合** + 互斥规则 |
| 动作/命令原语 | 架构 | 控制层、执行层 | 原语集合 + 超时语义 |
| 资产/配置格式 | 识别层 | 消费方、热更新 | 版本、阈值、组织方式 |
| 事件/日志 | 架构 | 全部 | 结构化 schema |
| 参数 schema | 架构 | 决策层、运维 | 参数、默认值、单位 |

**"封闭集合"是重点**：词表必须是一个能被签字确认的有限列表。不封闭，并行单元各自往里加，最后没人知道全集。

**每个契约必须有唯一写者。** 这是唯一能防止"热心地各自改接口"的结构性手段。

## 三、五个必须先回答的架构问题

每一个都会改变切分方式，所以必须在切任务之前定。

| # | 问题 | 不定会怎样 | 倾向 |
|---|---|---|---|
| 1 | 坐标/单位：绝对值还是归一化？ | 换规格后全部资产静默作废 | 归一化 |
| 2 | 时间语义：`sleep` 还是 `wait_until(条件, 超时)`？ | 固定等待是最大不稳定源 | 只允许后者 |
| 3 | 状态判定：单次观测还是 N 次一致？ | 中间态引发状态抖动 | N 次一致才转移 |
| 4 | 置信度：二元还是分级？ | "未知"变成碰运气而非设计 | 三级：确定/灰区/未知 |
| 5 | 决策：纯函数还是带内部状态？ | 无法离线验证、无法回放、不能并行 | 纯函数 + 外部注入历史 |

第 5 条杠杆最大：决策做成纯函数，就能**完全脱离真实系统开发**——喂合成输入、跑单测、并行写。

## 四、桩：契约要可执行，不只是被声明

只冻结文档**仍然会阻塞**。三个条件缺一不可：

| 条件 | 缺了会怎样 |
|---|---|
| ① 接口窄（契约数量少） | 协商成本回到平方级 |
| ② **桩可执行** | 下游仍要等上游真实实现，只是等得更文明 |
| ③ **每个单元有独立验收夹具** | 无法判断是否完成，只能等集成时发现 |

②③ 才是"不阻塞"的实质：**把"等待别人的产物"换成"对着冻结的桩开发和验收"**。

由此得出可派发单元的定义——**不是"最小工作单元"，而是"最小的、可以被独立验收的单元"**。二者经常差很远：一个最小工作单元可能必须等别人；一个可独立验收单元往往要稍大，大到自带验收装置。

## 五、骨架（L5）

> **骨架是 L2/L3 的验收测试，不是实现的开始。**

它用最小代码把所有契约串一遍：

- 跑通 → 契约至少**可执行**，可以往下切
- 跑不通 → 契约错，**此时返工最便宜**

骨架的产出物是一个判断（"架构是否成立"），不是功能。所以"先搭个骨架"如果被当成"开始写功能"，就已经走偏了。

### 什么时候需要独立的 L5（v0.2 修正）

旧判据"是否共享同一个可运行物"**不成立**——一个一天写完的脚本也共享同一个可运行物，但它不需要骨架级。

正确判据：

> **第一个端到端验证点，是否昂贵或不可逆？**

| 后果成本 | L5 形态 | 例子 |
|---|---|---|
| **便宜**（可重跑、可回滚、不伤钱不伤人） | **合并**：L5 与第一片重合，不单独成级 | 一个每日简报脚本，"手动跑一次发给自己"就是骨架 |
| **中等**（有真实副作用但可承受） | **正常**：在真实环境上跑一条最薄路径 | 用小号试自动化 |
| **昂贵或不可逆**（钱、生产数据、对外承诺） | **前移并换环境**：先在模拟/沙箱里跑，且成为接真实环境前的硬门禁 | 交易系统必须先回测骨架 → 模拟盘，才允许接真钱 |

推论：**L5 的位置不固定。** 后果越不可逆，它越靠前——对交易系统，回测骨架几乎是最先要做的东西，排在建契约之前也不奇怪。阶梯是依赖消除的顺序，不是固定工位的流水线。

档位差异：

- **M 档**：端到端空壳，所有接口接通，跑起来输出"我什么都没做"
- **S 档**：最薄的垂直切片，贯穿全链但只做一条路径

## 六、任务卡（L6，M 档）

```
目标：一句话，可验收
依赖契约：<名称> v<版本>
输入：读哪些文件，精确到节
输出：创建/修改哪些文件；明确不许碰哪些
验收：命令 + 期望输出（不是"实现正确"）
边界：不许改契约。发现契约不足 → 停下报告
回滚：失败时怎么干净丢弃
返工理由：（硬字段，发生时必填）分类：理解 / 假设 / 验收不可测 / 切分丢约束 / 上下文丢失 / 实现跑偏
```

**返工理由是硬字段**：任务卡上留空位，一旦这张卡返工就必须填。不用写故事，写清"哪一类 + 一句话"。它不是复盘，是复盘的原料——复盘可以在别的流程做，但理由不记，事后就再也拿不到了。

**星形 DAG 判据**：每张卡只依赖契约、不依赖其他卡 → 任何顺序都能开工，任何人先完成都不影响别人。

**一旦画出依赖链（B 必须在 A 之后），那就是缺了一个契约**——如果 B 真的需要 A 的产出，那 A 的产出本应是一个冻结产物（契约、资产、数据文件），而不是运行时依赖。

> 切任务时看到链，先别排顺序，回去找那个缺失的共享物。

## 七、派发与两阶段 review（L7，M 档）

1. **一次只合一个**（即使并行开发）
2. 每合一个：跑**契约符合性检查** + 冒烟
3. 两阶段 review：先看**规格符合性**（是否只做了卡里的事），再看**代码质量**
4. 每个并行组完成，跑一次端到端空壳

第 3 条的顺序不能反：先审规格符合性，否则你会先花时间美化一段本来就不该写的代码。

## 八、单人档的等价物

单人没有"并行单元"，但有**上下文重置**——每次重置都是一次交接给失忆的继任者。

| M 档概念 | S 档等价物 |
|---|---|
| 契约文档 | **代码里的类型定义**（文档会腐坏，类型被强制） |
| 桩 | 固定输入夹具 |
| 任务卡 | 带完成判据的切片（粒度 = 一次上下文） |
| 两阶段 review | 新上下文复读（把产物交给干净会话，只问"满足规格吗、哪里不对"） |
| 集成 | 每片收尾仪式 |

S 档只需要把**真正被反复碰的 3–4 个**契约写成类型，不必凑满六个。
