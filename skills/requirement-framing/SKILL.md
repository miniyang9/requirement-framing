# Requirement Framing

把一个"种子"变成可审查的规格——**在任何人开始拆任务之前**。

## 三条信条

1. **输入是种子，不是规格。** 用户那几句话说的是"什么事、大概什么形状"，不是可验证的东西。默认动作不是补全它，而是展开它。
2. **先展开，后提问。** 先走清单，把"你知道但用户没说"的倒出来；再只问自己判断不了的。先问问题，等于让用户替你做功课。
3. **展开的产物在形态上不能是任务列表。** 只要产物是列表，模型就会一路收敛到底。展开的产物必须是**带状态的判定**。

## 门禁（HARD-GATE）

> **未决问题没有全部得到用户回答、规模没有选定之前，禁止创建任何交付物。**

"创建交付物"包括，且不限于：

- 写代码、脚手架、测试、配置样例、部署脚本
- 建项目目录（`src/`、`app/`、`<项目名>/` 这类）
- 装依赖、初始化仓库、生成 lockfile

**最容易被放行的借口，一律不成立**：

> "这部分和未决问题无关，我先做掉。"

这个借口可以穿过任何门禁，因为总能找到一块"看起来无关"的部分。

**唯一例外**：只读探查，以及 `.tmp/` 里的一次性脚本（见"签字前允许什么"）。

### 签字状态

frame 文档顶部必须有 `状态：` 字段。

| 状态 | 含义 | 允许的动作 |
|---|---|---|
| **待答** | 还有问题没问，或有问未答 | 只读、提问 |
| **待签** | 问完了，等用户确认范围与规模 | 只读；可写回 frame 文档本身 |
| **已签** | 用户显式确认过 | 可以开工 |

三条判据：

1. **"文档存在" ≠ "已签"。** 上一轮留下的 frame 文档默认是"待签"，不是许可证。
2. **用户提问 ≠ 用户批准。** 他在问你要答案，不是给你开工许可。
3. **新答案引入新的未知 → 状态回退到"待签"。** 例如通道从邮件改成微信，原有假设作废。

### 签字前允许什么

只有两件事：

1. **只读探查**：读文件、查文档、问用户
2. **一次性临时脚本**，放 `.tmp/`，且不进入交付物目录

**探针的产出必须是结论，不是代码。** 结论写回 frame 文档的"实测发现"。你准备在项目里创建第一个文件时，就已经越线了。

## 加载后的第一条回复

必须包含三行，缺一不可：

```
档位：T0 直接做 / T1 轻量 / T2 全量
未决：Q1 …／Q2 …（没有就写"无"）
承诺：在收到这些回答前，我不会创建任何文件。
```

第三行是承诺句，不是客套。上一版缺了它，实测出现过"判了档位、问了问题、然后直接开始建目录"。

## 第 0 步：领域闸门

本 skill 服务**"会重复运行的产物"**：脚本、服务、工具、agent、定时推送、监控、机器人，或对存量代码库的成体系改造。

判据只有一条：

> 交付物是**会被执行不止一次**的东西，还是**一次性的回答 / 文档**？

| 需求 | 判定 | 动作 |
|---|---|---|
| 脚本 / 服务 / 工具 / agent | 是 | 进入第 1 步 |
| 定时推送 / 每日简报 / 监控 / 机器人 | **是**——哪怕实现只是一条调度器条目，一行代码都不写 | 进入第 1 步 |
| 成体系地改造存量代码库 | 是 | 进入第 1 步 |
| 一次性写个脚本、跑完就丢 | **T1** | 走轻量，但口径仍要先定 |
| 一次性回答 / 方案 / 调研 / 汇报 / 文章 | **不是** | 退化 |
| 策划活动、设计流程、组织安排 | **不是** | 退化 |
| 混合（"做个产品，含技术方案 + 运营方案"） | **部分** | **只对软件部分走流程**，其余回正常沟通；两者不要混在一份文档里 |

**为什么把"定时推送"也算进来**：它的实现可以只是一个调度器条目，不需要写一行代码——但它**会重复运行**。重复运行意味着任何一处口径含糊，都会每天稳定地产出错的答案，而不是错一次。

**判断时不要看实现形态**（代码 / 调度器 / 表格 / 人工流程），只看：它是不是会反复执行、每次都产出同一个"结论"。

### 不确定时不要猜

问一句（一句话，不要列选项）：

> "这个东西最后要交的是能跑的代码，还是一份文档/方案？"

### 退化之后做什么

"退化"不等于敷衍。它意味着：

- **不**产出 frame 文档、**不**判档位、**不**设门禁、**不**逐项走横切面
- **仍然**按正常对话澄清目标、给建议、必要时给结构化输出
- 但要明确说一句："这不是重复运行的产物，我不启用立项展开。"——让用户知道你**选择**了不启用，而不是漏了它

### 为什么闸门放最前面

本流程的成本主要花在"逼你想清楚可验证的东西"上。对一份方案或一次活动策划，这个要求是错位的：它们的验收不在重复运行结果里。**用错工具比不用工具更糟。**

## 第 1 步：分流（先算流程税）

| 输入长什么样 | 档 | 走哪些级 |
|---|---|---|
| 一句话已指定单点修改（"把图标改成矢车菊蓝"） | **T0** | 直接做，说一句你做了什么。**不启动本流程** |
| 一句话描述了一个可独立验证的功能，且 <1 天 | **T1** | 只走 L1 的"一页五问"，**拿到回答后**才动手。跳过 L2–L7 |
| 一句话描述了一个工程 / 系统 / 平台 | **T2** | 全流程 L1–L7 |
| 已经在拆任务，或要求派发给多个 agent | **T2** | 全流程，**先回退到 L1** |

**必须显式输出一行档位判定**，例如："档位：T1，因为单产物、<1 天、失败可承受、无需并行。" 不写这句，档位会默认滑向 T2。

**成本不在 L1，在 L2–L5。** L1 无论大小都要走（T1 约半小时到一小时）；真正压死小活的是"必须先出架构和契约"。所以：

- T1 的 L1 = 一页五问（体量 / 验收 / 不做 / **最大歧义** / 失败怎么办）
- T1 **只走** 5 问，不逐项走 17 项横切面。这是刻意的减配，不是遗漏
- T1 的唯一硬要求是：**最大歧义必须在动手前解掉**，因为那是唯一会让你做错东西的地方

## 第 2 步：L1 立项展开（六件套）

产出 `docs/frame/<slug>.md`，**顶部先写 `状态：待答`**，并列出未决问题。**本轮禁止输出任务列表、文件路径、实现步骤、代码。**

1. **体量判定** — 分档 + 依据 + "判断错一档的后果"（判小会怎样、判大会怎样）
2. **隐含工作包** — 必须做 / 可能要做 / 建议不做。每条标 `[推断]`（我补的）或 `[你说过]`
3. **两遍扫描** — 先按层扫 17 项横切面，再按角色扫 5 个视角（都见 `references/cross-sections.md`），逐项给 `已有 / 待定（取决于什么）/ 不适用（为什么）`。**不许合并、不许跳过、不许写成散文。**
4. **决策点** — 选项 / 推荐 / 可逆性 / 晚定代价。按"晚定代价"降序
5. **三种规模方案** — 最小可用 / 正规 / 平台化。各自**放弃什么、锁死什么**（只给放弃项的方案是假方案）
6. **失败预演** — 三个死法 + 最早信号 + 对策

末尾：**最多 5 个问题**，按"影响 × 不确定度"排序，每题带推荐答案。

**周期产出类**（定时推送 / 日报 / 监控）的五问固定为：**口径**（"最热 / 活跃 / 异常"到底按什么算）+ **数据源与失败告警** + **投递通道** + **时区与触发** + **幂等与重跑**。这五项里，口径永远排第一：它含糊，后面四项做得再好都是每天准时产出错误答案。

### 提问纪律（三条，缺一条就退化成问卷）

**① 先分类，再决定问谁。** 每个未决点先判它是哪一类：

| 类型 | 判准 | 动作 |
|---|---|---|
| **可自查事实** | 文件 / 代码 / git / 只读命令查得到 | **自己查，不许问用户** |
| **用户持有的事实** | 仓库里没有、只有他知道（现场状况、外部系统行为、未入库的约束） | 问；可附"我猜是 X" |
| **决策** | 取舍、偏好、优先级、业务判断 | 问，必须由用户拍板 |

问用户一个自己能查到的事，是最快的失信方式；把决策当事实自己填，是最贵的越线。

**② 一次只问一题。** 预算仍是 5 题，但形式必须串行：问一题、等回答、再问下一题。一次丢五题，用户只会挑好答的答，剩下的变成你的假设。

**③ 质量门：每个问题都要"具体到一句话能回答"，并附立场明确的建议答案。**

- ❌ "要考虑安全性" / "需要注意性能" / "建议做好错误处理"
- ✅ "同一笔订单重复提交两次，第二次拦在前端还是后端做幂等？**建议后端用 client_request_id 做幂等键，前端同时 disable 按钮**"
- ✅ "用户填到一半离开页面，草稿保留吗？**建议不保留，但弹确认框**"

建议答案要写成"建议 A，因为 B"。写"看你的需求"等于没给。

**自检**：如果横切面 17 项全都"很重要"，说明在写套话。真实系统里一定有若干项应当判"不适用"。

## 第 3 步：人审与收缩

交给用户，只要他做四件事：划掉不适用的、纠正 `[推断]`、回答 5 问、选规模。

**收敛前先复述一遍。** 把谈定的东西压成一句话，问用户：

> "别人只读这一行，会不会得到同样的结果？"

这一步比"签字"更便宜，也更难糊弄——签字容易，复述难装。复述不过关，说明还有没谈拢的地方，回到第 2 步。

**用户回复后做两件事**：把 `状态：` 改成"待签"或"已签"，并把每处回答写回文档。

**状态不是"已签"之前不要进第 4 步。** 这一步的产出是"签字"，不是"同意"。

## 第 4–7 步：按档位展开

先定档，读 `references/modes.md` 的对照表。

| 级 | S 档（单人 / 单 agent） | M 档（多人 / 多 agent） |
|---|---|---|
| L2 架构 | 一页图，能画在一屏内 | 分层、数据所有权、失败隔离 |
| L3 契约 | **写在代码里的类型** | 契约文档 + 版本号 + 唯一写者 |
| L4 决策 | 四行决策日志 | ADR（含被否决的替代方案） |
| L5 骨架 | 最薄的**垂直切片** | 端到端**空壳**，接口全通 |
| L6 切片 | 粒度 = 一次上下文窗口 | 任务卡 + **星形**依赖 DAG |
| L7 节奏 | 每片五步仪式 | 派发 + 两阶段 review |

契约与切片的细则见 `references/contracts.md`。

两档共同的硬约束：

- **L3 每个契约必须有一个唯一写者**，其余只读。
- **L5 骨架是 L2/L3 的验收测试**，不是实现的开始。骨架跑不通 → 回 L2/L3，不是往下走。
- **切任务时看到依赖链，先别排顺序**——链意味着某个该冻结的东西留在了运行时，回去找它。

## 铁律

**M 档**：

> 任务卡里发现契约不足：**停下来报告，不许自行扩展契约。**

并行子 agent 的头号失败模式不是做错，是热心地各自改接口。

**S 档**：

> 任何在上下文重置后还需要知道的东西，必须落盘。

每片收尾写四行：做了什么 / 没做什么 / 下次从哪开始 / **返工理由（发生时必填）**。返工理由只记分类，不写故事；分类见 `references/contracts.md`。

## 红旗自省

| 你正在想的 | 现实 |
|---|---|
| "这个我不确定，直接问用户吧" | 先判三分类。文件 / 代码 / git 能查到的先查；问一个自己查得到的事，是最快的失信 |
| "用宿主自带的定时器排一个任务就交差" | 那只是投递方式，不是需求。口径没定，它会每天准时产出错的答案 |
| "这个公式我随手定一个，透明就行" | 透明 ≠ 用户认可。"最热 / 活跃 / 异常"的定义必须由用户选，不能由发明者定 |
| "这块和未决问题无关，我先做掉" | 这是最贵的借口。无关性由未签字的人判断，不算数 |
| "用户在问我问题，说明他在推进" | 提问是在**要答案**，不是给**开工许可** |
| "文档已经存在了，照着做就行" | 存在 ≠ 已签。上一轮留下的默认是"待签" |
| "这个需求也该走一遍流程" | 先过领域闸门。一次性回答 / 方案 / 活动策划不是本流程的对象 |
| "先把最容易做的验证一下" | 你冻结错了层。先问它属于哪一级 |
| "架构等写完再补" | 架构不是细化，它是并行的前提 |
| "用户已经说清楚了" | 一句话能说清的只有单点修改 |
| "我先把默认值填上" | 好，但必须**说出来**。没说出口的默认值等于剥夺了用户否决它的机会 |
| "这就是几个独立任务" | 那你应该能画出星形 DAG。画不出来就是缺契约 |
| "先给个方案让他看" | 一个方案是替他选；三个方案才是让他选 |
| "先把代码骨架搭起来" | 骨架的产出必须是"架构是否成立"这个判断，不是功能 |

## 与现有方法的关系

- L1 ↔ BMAD 的 brief/PRD 层、OpenSpec 的 `explore`（"never writes code"）
- 提问纪律 ↔ grill / ouroboros interview（一次一题、附建议答案、能查的不问）
- 五角色扫描 ↔ requirement-gap-finder（PM / UX / 后端 / 前端 / QA 各扫一遍）
- L3 ↔ spec-kit 的 spec 实体、OpenSpec 的 `design.md`
- **L5 骨架是现有框架普遍缺失的一级**——它们都是"文档 → 任务"，中间没有可运行验证
- L6 ↔ spec-kit 的 `tasks.md`（精确到文件 + 验证）
- L7 ↔ superpowers 的 `subagent-driven-development`（每任务新 subagent + 两阶段 review）

## 产出物

```
docs/frame/<slug>.md           # L1 六件套（顶部带 状态：）
docs/arch/01-architecture.md   # L2
docs/arch/02-contracts.md      # L3（S 档可省，改用代码类型）
docs/arch/03-decisions.md      # L4
docs/arch/04-tasks.md          # L6
```

S 档可把 01–04 并成一个 `<slug>.arch.md`。但**不要省掉 L3 和 L5**——它们是"便宜的证伪"，砍掉不是变快，是把纠错点从半小时推到三周后。

**示例与案例必须放 `examples/`，绝不放在 `docs/frame/`。** 两者同路径会导致下一轮把示例当成已签的规格沿用——这个坑已经踩过一次。
