# Requirement Framing

把一个"种子"变成可审查的规格——**在任何人开始拆任务之前**。

**本 skill 只负责 L1（立项）**：从一句话到一份签了字的 frame + 一个交接块。架构、契约、切片、派发不在范围内，见"第 5 步：交棒"。

## 三条信条

1. **输入是种子，不是规格。** 那几句话说的是"什么事、大概什么形状"，不是可验证的东西。默认动作不是补全它，而是展开它。
2. **先展开，后提问。** 先走清单把"你知道但用户没说"的倒出来，再只问自己判断不了的。先问问题，等于让用户替你做功课。
3. **展开的产物在形态上不能是任务列表。** 只要产物是列表，就会一路收敛到底。

## 门禁（HARD-GATE）

> **未决问题没有全部得到用户回答、范围方案与执行档没有选定之前，禁止创建任何交付物。**

包括：写代码 / 脚手架 / 测试 / 配置样例 / 部署脚本；建项目目录；装依赖 / 初始化仓库 / lockfile。

**唯一例外**：只读探查，以及 `.tmp/` 里的一次性脚本。**探针的产出必须是结论，不是代码。**

万能借口，一律不成立：

> "这部分和未决问题无关，我先做掉。"

### 签字状态

frame 文档顶部必须有 `状态：`。

| 状态 | 允许的动作 |
|---|---|
| **待答** | 只读、提问 |
| **待签** | 只读；可写回文档本身 |
| **已签** | 可以开工（本 skill 范围内：可以产出交接块） |

五条判据：**文档存在 ≠ 已签**（上一轮留下的默认"待签"）；**用户提问 ≠ 用户批准**；**新答案引入新未知 → 回退"待签"**；**执行档没写进文档 = 不能签**；**已签只授权 frame 里写明的范围**——加需求、扩范围都是新的未知，先回退"待签"再谈。

## 加载后的第一条回复

```
体量档：T0 / T1 / T2
未决：Q1 …／Q2 …（没有写"无"）
承诺：在收到这些回答前，我不会创建任何文件。
```

## 第 0 步：领域闸门

只服务**会重复运行的产物**。判据：它会被执行不止一次，还是一次性回答？

| 需求 | 判定 |
|---|---|
| 脚本 / 服务 / 工具 / agent / 改造存量代码库 | 是 |
| 定时推送 / 日报 / 监控 / 机器人 | **是**——哪怕实现只是一条调度器条目 |
| 一次性脚本，跑完就丢 | T1，但口径仍要先定 |
| 一次性回答 / 方案 / 调研 / 汇报 / 文章 / 活动策划 | 不是，退化 |

理由：重复运行意味着任何一处口径含糊，都会**每天稳定产出错的答案**，而不是错一次。别看实现形态（代码 / 调度器 / 表格 / 人工流程），只看它会不会反复执行。

**不确定就问一句**："这个最后要交的是能跑的代码，还是一份文档/方案？"

**退化 ≠ 敷衍**：不建档、不判体量档、不设门禁，但仍正常澄清与给建议，并明说"这不是重复运行的产物，我不启用立项展开"——让用户知道你**选择**了不启用。

## 第 1 步：定体量档

**判据只有一条：这次交付要跨几个"可独立验收单元"？**

| 输入 | 体量档 | 走哪些级 |
|---|---|---|
| 单点修改，1 个单元（"把图标改成矢车菊蓝"） | **T0** | 直接做，不启动流程 |
| 1 个可独立验收单元，<1 天 | **T1** | 只走"一页五问"，**拿到回答后**才动手 |
| 多个可独立验收单元 | **T2** | 走完 L1（第 0–5 步） |
| 已在拆任务或要派发 | **T2** | 先回退到 L1 |

"工程 / 平台"不是判据，只是"通常跨很多单元"的症状。范围收窄（单点修改）是用户已经替你切好的结果，不是第二个判据。

**必须显式输出一行判定**，否则会默认滑向 T2。

T1 的五问：体量 / 验收 / 不做 / **最大歧义** / 失败怎么办。T1 不逐项走 17 项横切面——这是刻意减配，不是遗漏。

### 三个轴，别混

同一份需求要定三件事，它们正交，而且**由不同的人定**：

| 轴 | 固定叫法 | 回答什么 | 谁定 |
|---|---|---|---|
| 体量 | **体量档** T0 / T1 / T2 | 跨几个可独立验收单元 | 模型判定，用户可推翻 |
| 范围 | **范围方案** 最小 / 正规 / 平台化 | 做多少；放弃什么、锁死什么 | **用户选** |
| 执行 | **执行档** S / M | 几个写者、怎么切 | 模型提议，**用户确认** |

**三个轴互不推出**：平台化可以是 S（一个人做久一点），最小可用也可以是 M（两人分头做前后端）。"选了平台化"不等于 M，"选了最小"也不等于不用切任务。

全文只用这三个固定叫法。看到"规模""档位"这类含糊词，一律替换成上面某一个。

## 第 2 步：L1 展开（六件套）

产出 `docs/frame/<slug>.md`，顶部先写三行：`状态：待答` / `体量档：T0·T1·T2` / `执行档：S 或 M（待确认）`。**本轮禁止任务列表、文件路径、实现步骤、代码。**

1. **体量判定** — 分档 + 依据 + 判错一档的后果
2. **隐含工作包** — 必须做 / 可能要做 / 建议不做；每条标 `[推断]` 或 `[你说过]`
3. **两遍扫描** — 先层（17 项）再角色（5 个），读 `references/cross-sections.md`；每项给 已有 / 待定（取决于什么）/ 不适用（为什么）/ **不做（理由 + 谁砍的）**
4. **决策点** — 选项 / 推荐 / 可逆性 / 晚定代价，按晚定代价降序。**决策点 = 问题池；提问 = 从池里按"影响 × 不确定度"取前 5 个**
5. **三种范围方案** — 最小 / 正规 / 平台化，各自**放弃什么、锁死什么**
6. **失败预演** — 三个死法 + 最早信号 + 对策

**提问前先读 `references/questioning.md`**：三分类决定问谁、一次只问一题、每题带立场明确的建议答案。最多 5 题。

自检：17 项全判"很重要" = 在写套话。真实系统里一定有若干项应当判"不适用"。

## 第 3 步：人审与收缩

用户做**五件事**：划掉不适用的、纠正 `[推断]`、答问、**选范围方案**、**确认执行档**。

三个轴的决策权见第 1 步的表。这里用户要定的是**范围方案**和**执行档**；体量档可推翻，但不必重选。

**收敛前先复述**：把目标压成一句话，问"别人只读这一行，会不会得到同样的结果？"。这比签字便宜，也更难糊弄；不过关就回第 2 步。

用户回复后：改 `状态：` 并回写文档。**不是"已签"不进第 4 步。**

## 第 4 步：产出交接块

签字之后，另写一页 `docs/frame/<slug>.handoff.md`。**它是 L1 的唯一出口，也是下游唯一要读的东西。**

必填七项：`范围` · `验收` · `三轴` · `已冻结` · `必须回答的设计问题` · `留给下游决定的` · `引用`。

模板、三条纪律、以及"不合格的交接块长什么样"，读 `references/handoff.md`。

## 第 5 步：交棒

| 级 | 谁做 | 本 skill 提供 |
|---|---|---|
| **L1 立项** | **本 skill** | 全部 |
| L2 架构 | `solution-design`（待建） | 交接块 |
| L3 契约 | 同上 | 交接块里的"已冻结"与"必须回答" |
| L4 决策记录 | 同上 | 同上 |
| L5 骨架 | 同上 | — |
| L6 切片 / L7 派发 | 执行流（subagent / workflow / 常规实现） | 交接块里的验收与执行档 |
| 编码 | 常规实现 | 门禁与验收标准 |

**交棒不是结束。** 交接完之后，如果下游反馈"交接块缺东西"，回到第 2 步补，而不是在下游就地发明。

B（`solution-design`）尚未建成；它的素材暂存仓库 `staging/solution-design/`，**不随本 skill 安装**。

## 最容易犯的六条

| 想法 | 现实 |
|---|---|
| "这个我不确定，直接问用户吧" | 先判三分类，能查的先查 |
| "体量档定了就够了" | 三个轴各答一件事：体量档答多大、范围方案答做多少、执行档答几个写者 |
| "这块和未决问题无关，我先做掉" | 最贵的借口，无关性由未签字的人判断 |
| "用户在问我问题，说明他在推进" | 提问是在要答案，不是给开工许可 |
| "文档已经存在了，照着做" | 存在 ≠ 已签 |
| "交接块等下游来问再说" | 交接块是本 skill 的出口。出口没写，等于没做完 |

完整 11 条见 `references/red-flags.md`。
