# 人代执行：agent 跑不了的阶段二

> **什么时候读**：阶段二需要真实环境，但 agent 没有手（浏览器、真机、硬件），而且找不到可用的自动化工具。

---

## 先确认真的没有工具

按顺序试，别跳：

1. **浏览器自动化**（Playwright / Puppeteer 类 MCP 或 CLI）——扩展、网页
2. **设备自动化**（Appium / ADB 类）——手机、模拟器
3. **桌面自动化**（computer-use 类）——本地原生程序
4. **有没有一条命令能代替点击**——`curl` 验接口、`openssl s_client` 验证书链、`systemctl status` 验服务

有 → agent 自己跑，**不用人**。三种都没有，才走人代。

**必须在 `blackbox.md` 里写明试过什么、为什么都不行。** 不写，下次还要从头纠结一遍。

## 交出去什么

一张操作单，**逐条对应一个用例**：

```
用例 B2-3 · 兼容共存 · 生产
准备：装好扩展（chrome://extensions → 加载已解压 → 选 dist/）
步骤：
  1. 打开三个标签页
  2. 点扩展图标 → 批量导出
  3. 看下载目录
期望：得到 .txt，含三个 URL，顺序与标签页一致
要带回来：下载的文件本身 + 扩展弹窗截图
```

**「要带回来什么」必须写清**——这是最容易含糊的一步，含糊就会出现「我做了，没问题」这种无法验证的回报。

## 带回来怎么用

- 拿到实际结果 + 证据 → 回填 `blackbox.md` 的「实际」「证据」两栏
- **人只说「没问题」但没给证据 → 记「未验证」，不算通过**
- **人拒绝执行**（没权限、不敢做）→ 记 `未覆盖（人拒绝执行：<原因>）`，**项目不因此卡死**

## 不许做的三件

- 把人代执行写成「已通过」却不带证据
- 跳过工具探测直接找人（「反正人能测」）
- 把操作单写成一大段散文（必须逐条对应用例）
