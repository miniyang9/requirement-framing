# 串行 / 派发 · 逐环节对照

> **什么时候读**：选片之前，或想知道派发到底多做什么之前。

---

## 差别

| 环节 | 串行（一个执行者） | 派发（≥2 条不相交的线） |
|---|---|---|
| 选片 | 一次上下文一片 | 一条线 = 一张任务卡 |
| 写 | 自己写 | 派卡：任务卡 + 唯一写者 + 不许改契约 |
| 验 | 跑 01/02 的验收判据 | 验收 + **契约符合性检查** |
| review | 新会话复读 | 两阶段：规格符合性 → 代码质量 |
| 收尾 | 六行台账（含 `收敛：`） | 六行 + **一次只合一个** |
| 收敛 | **每片重跑**，写进本片那一行 | 星形 DAG 全绿 + 端到端空壳 |

**派发不是「更严格」。** 它多出来的是防多个写者互相踩的设施（任务卡、契约符合性检查、合并节奏）。一条线就能干完的事用这些是纯开销。

## 什么时候不派发

- **边界切不开**（两条线要改同一个文件）→ 串行
- **每片太小**（合并与对齐的成本 > 并行省下的时间）→ 串行
- **只是因为「执行者闲着」** → 那不是理由。派发是为了缩短关键路径，不是为了用满执行者
