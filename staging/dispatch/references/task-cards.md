# 任务卡与派发（L6–L7）

C 的素材。等 `solution-design` 跑通、确实需要把方案拆给多个执行者时，再做成 skill。

## 任务卡（L6，M 档）

```
目标：一句话，可验收
依赖契约：<名称> v<版本>
输入：读哪些文件，精确到节
输出：创建/修改哪些文件；明确不许碰哪些
验收：命令 + 期望输出（不是"实现正确"）
边界：不许改契约。发现契约不足 → 停下报告
回滚：失败时怎么干净丢弃
返工理由：（硬字段，发生时必填）分类：理解 / 假设 / 验收不可测 / 切分丢约束 / 上下文丢失 / 实现跑偏 / 越线（签字前开工）
```

**返工理由是硬字段**：任务卡上留空位，一旦这张卡返工就必须填。不用写故事，写清"哪一类 + 一句话"。它不是复盘，是复盘的原料——复盘可以在别的流程做，但理由不记，事后就再也拿不到了。

**星形 DAG 判据**：每张卡只依赖契约、不依赖其他卡 → 任何顺序都能开工，任何人先完成都不影响别人。

**一旦画出依赖链（B 必须在 A 之后），那就是缺了一个契约**——如果 B 真的需要 A 的产出，那 A 的产出本应是一个冻结产物（契约、资产、数据文件），而不是运行时依赖。

> 切任务时看到链，先别排顺序，回去找那个缺失的共享物。

## 派发与两阶段 review（L7，M 档）

1. **一次只合一个**（即使并行开发）
2. 每合一个：跑**契约符合性检查** + 冒烟
3. 两阶段 review：先看**规格符合性**（是否只做了卡里的事），再看**代码质量**
4. 每个并行组完成，跑一次端到端空壳

第 3 条的顺序不能反：先审规格符合性，否则你会先花时间美化一段本来就不该写的代码。

## 单人档的替代

S 档没有"并行单元"，只有**上下文重置**。等价物是：

- 任务卡 → 带完成判据的切片（粒度 = 一次上下文）
- 两阶段 review → 新上下文复读
- 集成 → 每片收尾仪式（做了什么 / 没做什么 / 下次从哪开始 / 返工理由）
