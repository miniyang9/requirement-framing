## 0. 种子

> "当前希望做一个自动交易的机器人" `[你说过]`

这句话没有指定：**哪个市场、什么品种、什么频率、多少钱、什么策略**。而这五项里任何一项变动，都会改掉整个工程的形状。以下是把种子展开成规格的尝试。

## 1. 体量判定

**多 epic（粗估 25–40 会话）。**

**但它的风险等级高于案例 1**：CoC 的错误后果是一个小号，这里的错误后果是**不可逆的钱**。差别不在工作量，在“第一次可验证点能不能失败”——这一条直接改变 L5 的形态。

判定错一档的后果：

- **判小（当成脚本）** → 你会得到一个能下单的程序，但它没有对账、没有幂等、没有熔断。某天网络抖一下，它把同一笔单下了三次。
- **判大（当成量化平台）** → 两个月在做回测框架和参数搜索，而真正的问题（“这个策略到底有没有 edge”）一次都没被验证。

## 2. 横切面覆盖（17 项）

| # | 层面 | 状态 | 说明 |
|---|---|---|---|
| 1 | 目标 / 非目标 | **待定** | 三种完全不同的目标：验证某个策略有没有 edge / 稳定盈利 / 自动化执行你已有的判断。见 D1 |
| 2 | 用户 / 角色 / 权限 | **不适用** | 单一自有账户。一旦涉多账户或代客，变成牌照问题（见 D5） |
| 3 | 领域模型与数据 | **待定** | 订单、成交、持仓、权益、策略状态。关键不是这些实体，而是**本地视图与交易所视图的对账模型** |
| 4 | 系统边界与外部依赖 | **待定** | 交易所 API（限频、断线、维护、变更）、行情源、通知通道。这是全系统失败率最高的一层 |
| 5 | 架构与模块划分 | **建议形态** | 数据 → 信号（纯函数）→ **风控（独立，策略不可绕过）** → 执行（幂等）→ 对账 → 观测 |
| 6 | 关键流程与状态机 | **待定** | 订单状态机（新建/已报/部分成交/已成/已撤/**未知**）、持仓状态、系统状态（运行/只减仓/熔断/停机）。“未知”必须是一等状态，不能靠推断 |
| 7 | 非功能：性能 / 容量 / 并发 | **待定** | 频率决定一切：日线调仓和秒级是 10 倍工程量差。还要定“断线多久必须停机” |
| 8 | 安全与合规 | **硬约束** | 资金损失不可逆；API key 泄露即等于交出账户；所在辖区对自动化交易、税务、以及“代客”有不同要求。**这需要你自己确认，我不做法律判断** |
| 9 | 可观测性 | **必需** | 持仓、未实现盈亏、异常订单、**每笔决策的理由**。没有决策理由，你无法回答“它为什么买” |
| 10 | 部署与环境 | **待定** | 本地还是云主机。关键问题：**断网/断电时持仓暴露怎么办** |
| 11 | 迁移与兼容 | **不适用，但有等价物** | 无存量数据。等价物是：**策略版本升级时，已有持仓怎么处理**——这是本项目最危险的一次“迁移” |
| 12 | 错误处理与降级 | **必需** | 三级：可重试（网络）／降级（只减仓）／必须停机（对账不一致、key 失效、连续亏损超阈） |
| 13 | 测试与验收 | **最大空白** | 回测的诚实性：滑点、手续费、成交概率、未来函数。唯一可靠的路径是 回测 → 模拟盘 → 小资金 → 全量，每一步都要有准入门槛 |
| 14 | 发布 / 灰度 / 回滚 | **必需** | 策略与参数都版本化，能一键回旧版；新版本先用最小仓位灰度 |
| 15 | 成本与资源 | **待定** | 手续费、滑点、资金费率、云主机、数据订阅。**摩擦成本必须小于策略毛利**，否则回测再好看也是负的 |
| 16 | 演进与二期 | **待定** | 多策略、多品种、组合与相关性。一期如果把“单策略”写死，二期要重写 |
| 17 | **可交接性** | **必需** | 场景很具体：**凌晨三点持仓异常，你能不能照文档处置**。这份文档不是说明书，是应急预案 |

**自检**：17 项里 1 项不适用、1 项"不适用但等价物存在"。第 13 项是真正的空白。

## 3. 隐含工作包

### 必须做

| # | 工作包 | 为什么躲不掉 |
|---|---|---|
| 1 | 行情与账户数据接入（含断线重连） | 一切的地基 |
| 2 | 订单状态机 + **幂等下单** | 重复下单是最常见的事故，且后果直接是钱 |
| 3 | 持仓与资金**对账** | 不对账就一定会出现“本地以为平仓、实际还开着” |
| 4 | **风控层，独立且不可被策略绕过** | 让策略自己管风控，等于让它给自己判卷 |
| 5 | 策略纯函数（信号 = f(数据)） | 唯一能离线验证、能回放的形态 |
| 6 | 回测 / 模拟盘（含摩擦成本） | 没有它，你是在用真钱做实验 |
| 7 | 结构化日志 + 每笔决策理由 | 否则无法归因“为什么亏” |
| 8 | 密钥管理（权限最小化，**禁提币**） | key 泄露 = 账户清空 |
| 9 | 熔断与只减仓模式 | 出事时的唯一刹车 |

### 可能要做

| # | 工作包 | 触发条件 |
|---|---|---|
| 10 | 参数搜索与样本外验证 | 只有当策略已确认有 edge，且你要优化时 |
| 11 | 多品种 / 多策略调度 | 单策略跑稳定之后 |
| 12 | 告警（IM / 邮件） | 一旦脱离“人在旁边看” |
| 13 | 可视化看板 | 想长期跟踪时 |
| 14 | 策略版本化与一键回滚 | 一旦开始改策略 |

### 建议明确不做（本期）

| # | 工作包 | 理由 |
|---|---|---|
| 15 | 高频 / 做市 | 毫秒级延迟的工程量与成本是另一个量级 |
| 16 | 代客理财 / 多人账户 | 涉牌照与受托责任，性质变了 |
| 17 | 杠杆 / 合约（起步阶段） | 放大不可逆性，且增加强平这一独立风险源 |
| 18 | 用 ML 预测价格 | 在“有没有 edge”的验证框架建立之前，它只会加速过拟合 |

## 4. 决策点

### D1 · 目标（最重要）

| 档 | 内容 | 含义 |
|---|---|---|
| A 验证 edge | 先证明“这个策略在历史上和样本外都能赚” | 可能要几周，且**有可能结论是“没有”** |
| B 稳定盈利 | 以收益与回撤为目标 | 在 A 成立之前谈这个是空话 |
| C 执行已有判断 | 你已有人工决策，机器只负责执行 | 工程量最小，价值也最确定 |

- **推荐 A**。理由：这个项目的真实风险不是“写不出来”，而是“写出来了但策略本来就不赚钱”。A 能在几周内以接近零的成本给出答案，而且**答“没有”也是有价值的结果**。
- **可逆性**：低。选 B 会让你在验证之前投入真钱。
- **晚定代价**：极高。

### D2 · 市场与品种 `[推断：加密现货]`

- 若为加密现货：API 最开放、7×24、可小资金、无 T+1、摩擦成本结构清晰 → 最容易验证
- 若为 A 股：T+1、程序化交易有报备要求、券商接口受限
- 若为期货/合约：叠加杠杆、强平、资金费率
- 若为外汇：零售渠道的对手方风险

**这一个决定会改掉 3、4、7、8、15 五项。**

### D3 · 频率

日线调仓 / 小时级 / 分钟级 / 秒级。**推荐从日线或小时级开始**——摩擦成本占比低，且不需要低延迟基础设施。

### D4 · 策略类型

规则型 / 趋势 / 均值回归 / 套利 / ML。**推荐先做一个可解释的简单规则**：它不是最优策略，但它能验证整条链路，而且你能解释它的每一笔交易。

### D5 · 资金与归属

模拟盘 / 小资金 / 主资金。**推荐：模拟至少 4 周，再小资金至少 4 周。** 另外确认：这是自有资金还是他人资金——后者是性质变化，不是工程量变化。

### D6 · 风控归属

内嵌在策略里 / 独立模块不可绕过。**推荐后者**，这是唯一能让“策略写错”不变成“账户清零”的结构。

## 5. 三种规模方案

| | A 最小可用 | B 正规工程（推荐） | C 平台化 |
|---|---|---|---|
| 周期 | 3–5 天 | 4–8 周 | 3 个月+ |
| 内容 | 单策略、单品种、日线、信号只**建议**、下单手动确认 | 自动执行 + 独立风控 + 对账 + 告警 + 模拟→小资金分级准入 | 多策略多市场 + 回测框架 + 参数搜索 + 组合 |
| 放弃 | 自动化（还是你在点） | 多品种、ML、低延迟 | 短期可用性 |
| 锁死 | 无 | “单策略”写死的话，二期要重写调度层 | 大部分时间花在与收益无关的基础设施 |
| 何时选 | 只想验证想法 | 你确实要长期跑 | 你要管多笔钱 |

**推荐 B，且 B 的第一步不是下单，是回测与模拟盘。** 这与案例 1 相反——那里第一步是探针（验证能不能操作），这里第一步是**验证值不值得操作**。

## 6. 失败预演

**死法 1 · 根本没有 edge**
回测很漂亮，实盘立刻失效。最常见的原因不是 bug，是参数拟合了噪声。
*最早信号*：样本外一上手就衰减。
*对策*：**先固定策略再调参数**；留 30% 数据完全不动；把“没有 edge”当作一个合法结论。

**死法 2 · 摩擦吃掉利润**
回测按收盘价成交、零滑点、零手续费。实盘一加上去，正收益变负。
*最早信号*：回测加滑点+手续费后接近零。
*对策*：第一天就把摩擦成本放进回测，而不是最后才加。

**死法 3 · 意外裸仓**
断线、部分成交、重复下单、对账漂移——某天你发现仓位不是你以为的那个。
*最早信号*：本地持仓与交易所持仓出现差异，且没有对账去发现它。
*对策*：幂等下单 + 定时对账 + 对账不一致即进“只减仓”并告警。

## 8. L5 判定（本案例的特殊处）

案例 1 的不可逆后果是账号，可承受 → L5 是“在真实环境上点几下”。
**本案例的不可逆后果是钱，不可承受 → L5 必须前移成模拟环境。**

所以这里的骨架长这样：

```
回测骨架（历史数据 → 信号 → 模拟成交 → 对账 → 报表）
        ↑ 这一级必须跑通，才允许接交易所的模拟盘
模拟盘骨架（真实行情 → 模拟成交）
        ↑ 这一级必须跑满 4 周，才允许接真钱
```

**没有第二级之前接真钱，等于用账户余额当测试用例。**
